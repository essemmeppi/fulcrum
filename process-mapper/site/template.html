2 · Method

How a claim gets into the map

The point is not that a model can summarise documents. The point is that every element of the map can be checked by a person who has never seen the model. So the pipeline separates reading from reasoning, and verifies the reading before any reasoning happens.

Facts

Read each source alone

The model extracts atomic claims (a step, a rule, a deadline, a data source) and must copy a verbatim quote plus the nearest section marker for each.

Verify

Exact-match every quote

Code checks each quote against the source text. Quotes that do not appear verbatim are dropped before anything else happens.

Synthesise

Build the map from facts only

The model assembles steps, actors, rules and data from the verified facts, citing fact ids. A step with no fact behind it is marked inferred, not hidden.

Expand

Attach the provenance

Fact ids become provenance on every node, edge and rule. Click any step in the map to see the passages it rests on.

5 · Confidence

How sure the map is

Every step carries a confidence: our expected probability that it matches how the process really runs, from a fixed rubric (explicit in law or official guidance across several sources; explicit in one; implied; inferred). The public record describes the external side of the process, what the citizen does and receives, better than the internal side, and the figures show it. A process owner at Kela can validate steps; validated steps count as certain.
